## Concrete defects (file:line, problem, fix)

Paths are relative to the repo root.

### Phase 04

1. `phases/04-dashboards/01-model-the-data-a-dashboard-needs/README.md:7`. "the monthly chart skipped every Sunday": a monthly chart cannot skip a weekday, only a daily or weekly one can. Fix: say "the daily chart".
2. Same line. "a count of orders card double counted orders with several lines". The star schema built here keeps line grain (1,241 rows), so `COUNT` on `fact_sales` still double counts. The lesson never shows the fix. Fix: add a step with `COUNT(DISTINCT order_id)` = 620 (DAX `DISTINCTCOUNT`), or an order-header fact, and test it.
3. `.../01-.../README.md:35`. The reason "With one flat table, every visual carries every repeated column" is muddled. Fix: give the real reasons. Filters propagate one way from the one side to the many side. Several fact tables (sales, targets, budget) can share conformed dimensions at different grains. Integer keys compress better. Time intelligence needs a marked, gap-free date table.
4. `.../01-.../README.md:39` and `solution/solution.sql:26,49`. "survives a product being renamed": the key is `ROW_NUMBER() OVER (ORDER BY product)`, recomputed on every load and joined on the product name. A rename or a new product re-keys everything. Fix: say the keys here are rebuilt per load. Note that real surrogate keys are persisted (a key map table) and that the fact joins on a stable natural key (a SKU id). Optionally add a `product_id` column to the data.
5. `.../01-.../README.md` (no section). There is no weekday or month-name column, although the story is about Sundays. A useful addition is a `weekday` column plus a test that Sundays exist with 0 revenue.
6. `phases/04-dashboards/02-dax-measures-from-scratch/README.md:7` and `make_data.py:28`. The story says the retail shop closed in March 2025, but online sales are also zero that month. Fix: either drop only Retail rows in March 2025 (a better lesson: Online Sales LY still works, Retail growth is blank), or say the whole business paused.
7. `.../02-.../README.md:28`. CALCULATE is described as "add a filter to the current context". A boolean filter argument such as `sales[channel] = "Online"` REPLACES any existing filter on `sales[channel]` (it is `FILTER(ALL(sales[channel]), ...)`). With channel on rows, Online Sales shows the online total on the Retail row too, while the SQL `CASE WHEN` shows 0. This is a classic interview question. Fix: state the override rule, show `KEEPFILTERS` as the "add" version, and say the CASE WHEN equivalence holds only when channel is not on the visual.
8. `.../02-.../README.md:29,57`. `ALL(sales[category])` is mapped to `(SELECT SUM(amount) FROM sales)`. The subquery removes every filter (date, channel, slicers), while `ALL(category)` removes only the category filter. Fix: use `SUM(SUM(amount)) OVER ()` over the grouped result. It keeps the WHERE clause (other slicers) and drops only the GROUP BY dimension. Also mention `REMOVEFILTERS`, the modern spelling.
9. `.../02-.../README.md:30`. TOTALYTD "replace the date filter with 1 January to the current date". Fix: "to the last date in the current filter context".
10. `.../02-.../README.md:101` vs DAX at :125. The SQL sets `sales_ly` to 0 for March 2025, but DAX `Sales LY` is BLANK there. Worth one sentence, since a 0 on a card and a blank on a card mean different things.
11. `phases/04-dashboards/03-tableau-lod-expressions-in-sql/README.md:111-112`. The view is described as "Region and MONTH([Order Date])" with `{EXCLUDE MONTH([Order Date]) : ...}`. MONTH() is the month-of-year date part. The SQL uses year-month, which only matches because the data has one year. An EXCLUDE declaration also has to match the pill in the view, so the expression form is fragile. Fix: use exact-date month (MONTH-YEAR) in the view, and offer `{FIXED [Region] : SUM([Amount])}` as the robust alternative. Verify in Tableau before publishing (medium confidence on the expression-matching behaviour).
12. `phases/04-dashboards/04-draw-a-chart-from-scratch/README.md:25`. "Length is the visual property people compare most accurately". In the classic perception ranking, position on a common scale comes first and length after it. Fix: "position along a shared axis, which is what the end of a bar on a common baseline gives you". Also drop the unstated research claim or cite it.
13. `.../04-.../README.md:112`. The walk-through uses plain `escape(label)` inside an attribute, so a `"` in a label still breaks the XML. `solution/solution.py:77` handles it with `{'"': "&quot;"}`. Fix: use `xml.sax.saxutils.quoteattr`, or the same entity map, in the README.
14. `.../04-.../README.md` (whole file). The chart is never shown. Fix: commit the rendered `chart.svg` and embed it with `![...](chart.svg)`. GitHub renders SVG. Show a truncated-axis version next to it.
15. `.../04-.../test_lesson.py:54-58`. `choose_chart` maps 'time' to line and 'category' to bar, which tests nothing. Fix: extend it to a small decision table (distribution goes to histogram, part-to-whole with fewer than 5 parts goes to stacked bar or a sorted bar, relationship goes to scatter, ranking goes to sorted bar) and test it with ambiguous cases. Also `data-value` is never checked against the input values (test :79-86 trusts the learner's attribute).
16. Ordering: 04-04 uses `csv.DictReader`, lambdas, sort keys and string formatting before phase 05 teaches Python. Fix: move 04-04 after 05-01, or add a Python basics lesson before phase 04 (see the missing modules).

### Phase 05

17. `phases/05-python-for-analysts/01-clean-a-messy-csv/README.md:28` and `solution/solution.py:13`. `[\d,]+` accepts comma-only strings. `parse_amount("$,")` and `parse_amount("INR ,,,")` raise `ValueError: could not convert string to float: ''` instead of returning None (the `bad_amount` path), and `"$1,2,3"` parses to 123.0. Fix: require a leading digit, `(\d[\d,]*(?:\.\d+)?)`, and add these cases to `test_parse_amount`. Negative amounts and refunds (`-$50.00`) return None silently. Mention them.
18. `.../01-.../exercise.py:14` and README:23. `%b` in `strptime` depends on the locale and fails on non-English locales. One sentence would cover it.
19. `.../01-.../README.md:105` (Check yourself 4) teaches that the same id with different amounts is a conflict to report, but `clean_rows` has no `conflict` reason and the data has no such case. Fix: add one conflicting pair to `make_data.py`, a `conflict` drop reason, and a test.
20. `.../01-.../data/orders_raw.csv:2`. A customer in Austin pays in INR, and cities and currencies are random. Business realism: the brief says the shop sells in the US and India. Fix: tie the currency to the city, or make the mismatch a check the learner flags.
21. Beginner gap in 05-01. The regex `^(\$|USD|INR|RS\.?)\s*([\d,]+(?:\.\d+)?)$` is never explained piece by piece (`^`, `\s*`, `(?:...)`, `\.?`, the groups). 06-03 does this well. Copy that style.
22. `phases/05-python-for-analysts/02-reshape-wide-and-long/README.md:14`. "the round trip gives back the exact input" is true only because the input is sorted by region and then month. Shuffled input comes back in a different row order. Fix: say "the same rows" and compare sorted lists, or add a shuffled-input test.
23. `.../02-.../README.md:82,90`. "In Excel this is a pivot table." A pivot table aggregates duplicate pairs (SUM by default), while `pivot_wider` raises on them. That difference is the point of the lesson, so say it, and note that pandas `pivot` raises while `pivot_table` aggregates.
24. `phases/05-python-for-analysts/03-dates-weeks-and-time-zones/README.md:82`. The README says "Cut the report at the last complete week", but neither `week_over_week` nor the test does it, and the shipped IST table ends with the misleading -96.4% row. Fix: add `complete_weeks(weekly, data_end, zone)` and test that 2026-W04 is dropped.
25. `.../03-.../exercise.py:12-13`. "For real reports across the year use zoneinfo instead", but DST is never demonstrated. `zoneinfo` is stdlib in 3.9. Fix: an optional test using `zoneinfo.ZoneInfo("America/Los_Angeles")` that shows a 23-hour day in March, with `skipUnless` if tzdata is missing (Windows).
26. `phases/05-python-for-analysts/04-automate-the-weekly-report/README.md:30`. The refund rate uses orders placed this week, so recent weeks understate refunds that have not happened yet (refund lag). Add one line on this. It is exactly the kind of false improvement the -1.7 pts row could be.

28. `.../04-.../README.md:37`. "so it can run from a scheduler", but cron, Task Scheduler and GitHub Actions are never shown. Fix: add a 3-line cron example and a Windows equivalent as text.

Running `python3 solution/solution.py` (README:65) writes `phases/05-python-for-analysts/04-automate-the-weekly-report/reports/` into the lesson folder, and 07-03 suggests `writeup.md`. ### Phase 06

30. `phases/06-ai-for-analysts/` has no `README.md`. Every other phase in scope has one, and `05-04/README.md:112` links to the bare folder. Fix: add a phase README explaining fixtures vs live models, and the order.
31. `phases/06-ai-for-analysts/01-grade-an-llm-classifier/make_data.py:70`. The LLM label is drawn independently of the text, and there are only 16 distinct texts. The same sentence ("I want my money back for this order") gets both `refund` and `billing`. A learner who opens the CSV to do error analysis sees nonsense, and a real model at temperature 0 would be consistent. Fix: 400 distinct texts, with errors concentrated on genuinely ambiguous wording ("charged twice, please reverse it"). Error analysis by reading misclassified rows is then meaningful.
32. `.../01-.../README.md:69`. "Refund recall is 0.847, which passes" with n = 72 actual refunds. A 95% Wilson interval for recall runs roughly 0.75 to 0.91, so the pass is not established. Precision 61/75 has a Wilson interval of 0.711 to 0.885, so the "no" is robust. Fix: add a `wilson_interval` function (phase 02 already teaches CIs) and make the rule "the lower bound clears the bar".
33. `.../01-.../README.md:19`. "Treat the human label as the truth" with no caveat. Add: labels are noisy, double-label a sample, and measure agreement (Cohen's kappa). Also record the model name, prompt version and date with the fixture.
34. `phases/06-ai-for-analysts/02-check-llm-written-sql/README.md:30`. "If the question is about order (a top 3 list), ... the set of rows is still the right test." Two problems. (a) With ties at the LIMIT boundary, two correct queries return different sets. Q7 passes only because the tie at 2026-06-25 (orders 15 and 250) falls entirely inside the top 5. (b) When order is the answer (a ranking), sorting hides a wrong order. Fix: compare ordered when the trusted query has ORDER BY plus LIMIT, and tell learners to add tie-breakers.
35. `.../02-.../README.md:31`. "Compare values only, not column names": column ORDER still matters. `SELECT COUNT(*), country` vs `SELECT country, COUNT(*)` is classified `wrong rows` (verified). Fix: say so, or normalise by sorting values within each row, which has its own risks.
36. `.../02-.../README.md:29`. Rounding both sides to 2 places can split values that straddle a half-cent boundary. A tolerance compare (`abs(a - b) <= 0.005`) is safer.
37. `.../02-.../solution/solution.py:29-34`. `run_query` executes anything, including `DROP TABLE orders`. In 2026 the realistic setup is an agent running SQL. Fix: teach `PRAGMA query_only = ON` (or a `file:...?mode=ro` URI), reject anything that is not a single SELECT, add a row cap and a timeout via `set_progress_handler`, and test that a DELETE is refused. All of this is stdlib.
38. `.../02-.../README.md:7`. Tom wants "how often that SQL is wrong", but the sample is 8 queries. Fix: say 3/8 cannot estimate a rate (link to phase 02), and frame the output as a defect list, not a rate.
39. Methodology gap in 06-02. Execution match on ONE database is "execution accuracy", which passes wrong queries that happen to agree on this data. Q8's `COUNT(order_id)` vs `COUNT(*)` agrees here, and a missing filter can agree too. Fix: add a second "adversarial" database (test-suite accuracy): run every pair on two or three databases built to separate common mistakes (NULLs, customers with no orders, ties, an extra status value).
40. `phases/06-ai-for-analysts/03-catch-made-up-numbers/README.md:24`. The extractor turns typical LLM prose into wrong numbers (verified). "In H1 2026 revenue fell 3.2% to $1.5M." gives `[1, 2026, 3.2, 1.5]`. "-4.1%" loses its sign. "$51k" becomes 51. The count check would raise, which is safe, but the lesson does not say these cases exist. Fix: handle k/M/bn suffixes and a leading minus, skip years and quarter or half labels, and test them. Better still, make the 2026-style approach the main path: ask the model for structured claims (JSON with metric_id and value) and verify those (see the missing modules).
41. Soft unsourced claim, `.../02-.../README.md:23`: "Wrong column names and syntax from another SQL dialect are common." Fine as a teaching statement. Rephrase as "two failure types you will see" to avoid a frequency claim.

## What is excellent and must be preserved

- **Every README number is real.** Each quoted figure comes from the lesson's own seeded data and reproduces exactly. Keep the rule that prose numbers are computed, never typed.
- **The trap-first design.** Each lesson shows the plausible wrong answer failing on real data before the right one: LAG vs calendar shift (04-02), distinct vs new customers (04-03), the truncated axis 4.36x vs 1.28x (04-04), dedupe after normalising (05-01), %W vs ISO week (05-03), points vs percent (05-04), accuracy hiding refund precision (06-01), the inner join that cannot find missing rows (06-02), right inputs with a wrong growth figure (06-03), "excel at" and R&D (07-01), OFFSET with ties and islands with duplicate days (07-02), censoring before churn (07-03). This is the course's signature.
- **Honest limits sections.** 06-03 says what the checker cannot catch, 07-04 says why keyword matching is a starting point, 07-03 refuses a causal claim, and 05-04's make_data admits the random draw went against the setting.
- **The "the tool is just the interface" framing of phase 04.** It is the right way to teach Power BI and Tableau offline, and the DAX and Tableau reference blocks are labelled as not run.
- **Fixtures labelled as fixtures** in phase 06 ("No API is called").
- **Small-function tests on tiny hand-made inputs** (06-01 tiny_rows, 06-02 tiny classify, 04-04 small values, 05-03 synthetic weekly dicts). These resist hard-coding and should be copied into the SQL lessons.
- **Business decisions as outputs**: meets_rule yes/no, learn_next, the write-up generator, the Monday report file.
- **Style compliance**: no dashes or curly quotes anywhere in scope.

## Exercise and test quality (cross-cutting)

- The SQL lessons (04-01, 04-02, 04-03, 07-02) test against one committed dataset only, so a `VALUES (...)` list of hard-coded rows passes. That is the realistic risk in 2026, when a learner pastes the exercise into an assistant. Fix: give `make_data.py` a `seed` argument, and have each test also build a second in-memory dataset with another seed and compare the learner's query to a Python reference on both. This doubles as a lesson in test-suite thinking for NL-to-SQL (defect 39).
- 04-01 does not check that `fact_sales` holds only keys and numbers (text columns would pass).
- Tests verify outputs, not understanding. The Check yourself answers sit in an open `<details>` block. The tutor explain-back step above is the right complement, rather than hiding answers.

## Gaps: recommended missing lessons and modules, in learning order

Levels: B = beginner, I = intermediate, A = advanced. "T" = runnable stdlib test possible. "G" = guide page, no test.

### Before phase 04 (or as 05-00): Python first steps

1. **Python for spreadsheet people** (B, T). Question: can you total a column of a CSV without Excel? Values, lists, dicts, loops, functions, reading a CSV, reading an error message. Needed because 04-04, all of 05 and all of 06 assume fluency.

### Phase 04 additions (BI and spreadsheets)

2. **Lookups and SUMIFS like Excel** (B, T). Question: why does the VLOOKUP total not match finance? Exact vs approximate match on a sorted band table, #N/A, duplicate keys returning the first match, XLOOKUP. The semantics are rebuilt in Python, and the learner can also export their Excel result as CSV for the test to check.
3. **Pivot tables and Power Query steps** (B, T). Question: can next month's file be merged with one click? Applied steps as an ordered, replayable list (promote headers, change types, unpivot, merge = join, append, group by). The lesson rebuilds the step list in Python and tests a re-run on a new file.
4. **Relationships, role-playing dates and many-to-many** (I, T). Question: why does revenue by ship month differ from revenue by order month? Covers two date keys, an inactive relationship (DAX `USERELATIONSHIP` as a reference block) and a bridge table, all in sqlite.
5. **One metric, one definition: the semantic layer** (I, T). Question: why do two dashboards show different active users? A metric registry (a dict or JSON of measure, filters and grain) compiled to SQL, with a test that two "dashboards" built from it agree. Reference blocks for a Power BI semantic model, LookML and dbt metrics.
6. **Slowly changing dimensions** (I, T). Question: which region was this customer in when they ordered? Type 2 rows with valid_from and valid_to, and point-in-time joins.
7. **Dashboard design and the line chart** (B to I, T). Question: what does the CEO see in five seconds? KPI card logic (value, comparison, target), a line chart SVG with a time axis, small multiples, colour-blind-safe palettes, and titles that state the takeaway. This extends 04-04's code.
8. **Row-level security** (I, T). Question: can each regional manager see only their region? A user-to-region mapping table filtering the fact table in SQL. Power BI RLS roles as a reference block.
9. **Tableau table calculations vs LOD** (I, T). Question: running total, rank or percent of total, and which should be computed where? The SQL equivalents of RUNNING_SUM and WINDOW_SUM, with "compute using" as PARTITION BY.

### Phase 05 additions (Python, EDA, APIs, data quality)

10. **Profile a table before you trust it (EDA)** (B, T). Question: is this table fit for the board number? Row counts, nulls, distinct counts, min and max, a text or SVG histogram, IQR outliers and an impossible-values check.
11. **Join two files in Python and prove nothing was lost** (B, T). One-to-one and one-to-many assertions and a row-count reconciliation.
12. **APIs and JSON** (I, T on a saved response). Question: how many analyst roles did the feed return this week? Parse nested JSON, page through it with offsets, flatten it to CSV and handle missing keys. The live `urllib` call is shown but not tested, and the test runs on a recorded response. Use `tools/build_job_market_snapshot.py` as the real example.
13. **More charts from scratch: histogram, scatter, line** (I, T). Bin choice, overplotting and a log scale.
14. **Data quality tests as code** (I, T). Question: would we have caught last week's broken load? not_null, unique, accepted_values, freshness, relationships and a row-count delta vs last load, which mirror dbt tests.
15. **From stdlib to pandas** (I, G plus an optional T skipped without pandas). A one-to-one map from each function the learner wrote (pivot_wider, count_by, clean_rows) to `pivot`, `pivot_table`, `melt`, `groupby`, `resample` and `merge`. This is honest about the stdlib constraint and covers the jobs that ask for pandas.

### New phase or 05 tail: modern data stack

16. **Warehouse layers: raw, staging, marts** (I, T). Question: why do we never edit raw data? ELT in sqlite views, with idempotent rebuilds.
17. **dbt from scratch** (I, T). Question: in what order must these 6 models build? SELECT models with `ref()` resolved by `graphlib.TopologicalSorter` (stdlib since 3.9), tests, and an incremental model by date partition.
18. **Orchestration: a tiny DAG runner** (I to A, T). Retries, idempotency, backfill by date and alerting on failure. Airflow, Dagster and cron appear as reference blocks.
19. **Git for analysts** (B, G, with an optional test that skips without git). Commit a query, read a diff, review a teammate's change.

### Phase 06 additions (GenAI for analysts, in order)

20. **What an LLM is, for an analyst** (B, G plus a T cost calculator). Tokens, context windows, nondeterminism, temperature, cost per 1,000 rows, and why a fixture records model, prompt and date.
21. **Prompt versions as experiments** (B to I, T on recorded outputs). Question: is prompt v2 better than v1 on the same 200 tickets? Paired comparison of two recorded output sets with a McNemar test (stdlib math).
22. **Structured output you can load** (I, T). Question: can we put the model's JSON straight into a table? A hand-written schema check for types, enums and required fields, plus repair and reject logic, run on recorded raw outputs that include malformed JSON, a wrong enum and a missing field.
23. **How big must an eval set be?** (I, T). Wilson intervals on precision and recall, a held-out split, and regression across two model versions. This extends 06-01 with phase 02 methods.
24. **Human in the loop: auto-route at a confidence threshold** (I, T). Question: how many tickets can we auto-route at 95% precision? A coverage vs precision curve from recorded confidences, the abstain option and a cost model.
25. **LLM as judge, and judging the judge** (I, T). A rubric, judge-vs-human agreement with Cohen's kappa, and a position-bias check by swapping answer order, all on recorded judge outputs.
26. **NL-to-SQL safely, version 2** (I to A, T). A read-only connection (`PRAGMA query_only`), a statement allowlist, row and time caps, test-suite accuracy on several databases, and an "ask a clarifying question" label for ambiguous questions.
27. **PII out before data goes to a model** (B to I, T). Redact emails, phones and ids with regex, hash join keys, and check that nothing leaked.
28. **RAG over the metrics glossary** (I, T). Question: which definition of active user did the bot cite? BM25 or TF-IDF from scratch, recall@k, answers that must cite a retrieved passage, and a grounding check on recorded answers.
29. **Audit an agent's work** (A, T on a recorded transcript). A recorded agent run as JSON (tool calls to `run_sql` and `read_file`, plus the final answer): check every tool call against an allowlist, recompute every number independently (reusing 06-02 and 06-03) and flag the step where it went wrong.
30. **MCP for analysts** (A, T for the message shape, G for wiring it to a client). Implement a stdlib JSON-RPC `tools/list` and `tools/call` handler for a read-only `run_sql` tool and test it by sending JSON requests over stdin. Connecting it to Claude Desktop or another client is guide-only.

### Phase 07 additions (interview and career)

31. **Role roadmaps from postings data** (B, T). Question: data analyst, BI developer, product analyst or analytics engineer: which skills differ? Run 07-01's extractor by title family on synthetic postings, cross-checked against `data/job-market` shares. The drop shows Excel at 41.8% (US) and 45.7% (IN), which supports adding modules 2 and 3.
32. **The metrics case interview** (I, partially T). Question: sign-ups fell 20%: walk me through it. Clarify the question, build a metric tree (reuses phase 03), segment and rule out instrumentation. The numbers are computed in the test, and the reasoning is assessed with a rubric checklist.
33. **The statistics interview round** (I, T). P-values, power and Simpson's paradox on a runnable dataset where the pooled and segmented answers disagree.
34. **The take-home assignment** (I, T for structure). Time-boxed, with a rubric checker for assumptions stated, a chart present, a recommendation and limitations.
35. **Resume bullets that are true** (B, T). A bullet linter for an action verb, a number and an outcome. Every number must exist in the learner's own project output (reusing 06-03's matcher), so no invented metrics.
36. **Behavioural answers in STAR form** (B, G).
37. **Publish the portfolio** (B, T for structure). Repo layout, README, a one-command run, the chart image and the data licence.
38. **Industry case studies** (I, T each). Fintech: approval funnel and default rate by cohort. Healthcare operations: clinic wait times and percentiles. Marketing: last-touch vs linear attribution. Supply chain: on-time delivery and the late-shipment metric tree. HR: attrition by tenure band with censoring. Each needs a named stakeholder and a decision, like the existing lessons.

## Topics that cannot be tested offline with stdlib, and how to teach them honestly

| Topic | Why not testable | Honest approach |
|---|---|---|
| Clicking in Power BI or Tableau (relationships view, slicers, formatting) | GUI and licensed software | Rebuild the logic in SQL (as phase 04 does). Add an optional "do it in the tool" task with a **golden numbers file**: the test prints the exact totals the learner should see in their visual, and the learner compares by eye. Optionally test a CSV the learner exports from the visual (Export data), which IS testable. |
| Excel pivots, XLOOKUP, Power Query UI | GUI | The same pattern: rebuild the semantics in Python, then test the learner's exported CSV of their pivot or query against the reference. |
| Live LLM API calls | Network, keys, cost, nondeterminism | Use **recorded fixtures with provenance** (model name, date, prompt hash, temperature), clearly labelled as recorded or simulated. Today's fixtures are simulated, so say so, and prefer real recorded outputs. Add an optional `live_run.py` that skips without a key and only re-records fixtures. Tests always run on fixtures. |
| Agents and tool use in a real client | Needs a model and a client | Audit recorded transcripts (module 29). The tool server side is testable (module 30). |
| MCP wiring into Claude Desktop or another client | External app | Guide page with config snippets. Test only the JSON-RPC handler. |
| dbt, Airflow, Snowflake, BigQuery | Installs and cloud | Rebuild the concepts in sqlite plus `graphlib`. Show real `dbt_project.yml`, model and test files as reference blocks marked "not run". |
| git and GitHub | A binary outside Python | Guide page, plus an optional test that uses `subprocess` to check repo state and calls `skipUnless(shutil.which("git"))`. |
| pandas | pip install | Optional tests with `skipUnless(importlib.util.find_spec("pandas"))`. The core lessons stay stdlib. |
| Time zones with DST | Windows lacks tzdata | Use `zoneinfo` with a skip when tzdata is missing. Keep fixed offsets as the guaranteed path. |
| Behavioural interviews, negotiation, networking | Not computational | Guide pages with structure checklists. No invented success-rate statistics. Any number must be a dated Real Analyst Jobs feed figure. |
